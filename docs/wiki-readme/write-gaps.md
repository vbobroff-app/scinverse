# Разрывы записи (Write Gaps)

> Пользовательское описание (to-be). Не спека разработки.  
> Технический канон — [`docs/dev/phase7h/write-gaps.md`](../dev/phase7h/write-gaps.md).  
> Слои T/C/W — [`layers.md`](layers.md) · инциденты — [`incident.md`](incident.md).

---

## 1. Зачем это нужно

Когда инструмент **стоит на запись**, сделки должны попадать в историю. Иногда на ганте
видно «дыру» — участок, где данных нет. Важно не путать две разные ситуации:

| Что видно | Что это значит | Нужно ли восстанавливать? |
|-----------|----------------|---------------------------|
| Запись включена, связь жива, сделок нет | **Тихий рынок** — система работала, рынок молчал | Нет |
| Запись включена, но в это время была поломка (обрыв / краш / тихий обрыв) | **Разрыв записи** — данные должны были писаться, но не писались | **Да** |

**Write Gap** — это как раз второй случай: объективный интервал «надо восстановить», без разбора
причины поломки. Причина (break / crash / ping) остаётся в журнале инцидентов и на ленте
соединения; для восстановления важен **факт и границы дыры**.

---

## 2. Когда запись «должна вестить»

**Намерение** — запись по инструменту включена (вручную или Recording Auto). Пока намерение есть,
система обязана принимать сделки.

Намерение — это не «Auto по расписанию соединения». Расписание связи только поднимает/опускает
линк; намерение появляется, когда реально стартовала запись инструмента.

---

## 3. Картина на ганте записи (Writers)

Слои дорожки инструмента (снизу вверх по смыслу):

1. **Намерение** — «стояло на запись».
2. **Живость** — «захват / связь в этот момент живы».
3. **Подложка** — пересечение намерения и живости (честный фон).
4. **Сделки** — яркие ячейки: реально была торговля.
5. **Write Gap** (по галке) — сплошной **красный**: здесь нужна дозагрузка.

Красный слой — **одного цвета**, без жёлтого / без маркеров «чья вина». Бинарность только у него:
либо дыра для восстановления, либо нет. Ячейки сделок остаются яркими поверх подложки.

Лента **соединения** (выше списка инструментов) по-прежнему показывает детали инцидентов
(break / crash, владельца). Это другой слой — про связь, не про «что бэкапить».

---

## 4. Как получается красный интервал

Два шага.

### Write Hole — дыра по сделкам

Есть намерение, и в этот период был (или ещё открыт) **инцидент**, пересекающийся с тишиной
сделок. Границы дыры — **не** по моменту детекта инцидента, а по сделкам:

- **влево** — последняя сделка до дыры;
- **вправо** — первая сделка после (или «сейчас», если инцидент ещё открыт).

Так границы самые точные: сделки пропадают раньше, чем система успевает открыть инцидент, и
возвращаются позже, чем связь формально восстановилась.

```text
|------ Write Hole (по сделкам) ------|
   |------ incident (детект) ------|
```

Тихий обрыв (нет сделок, пинг не проходит) тоже открывает инцидент — тот же путь, отдельного
правила не нужно.

Тихий рынок: намерение есть, сделок нет, **инцидента нет** → Write Hole нет → красного нет.

### Write Gap — дыра в рабочем окне

```text
Write Gap = Write Hole ∩ расписание записи
```

Вне торгового / desired-окна красного нет: восстанавливать нечего. Расписание **нарезает** дыру
(как нож), а не решает, был ли сбой.

Несколько инцидентов в одной тишине не важны: достаточно факта пересечения; края всё равно по
сделкам.

---

## 5. Зачем оператору

- На ганте сразу видно **где чинить историю**, а не только «где мигала связь».
- Интервалы Write Gap — параметры для будущего **восстановления сделок** (что именно дозагрузить).
- Галка слоя: можно смотреть подложку и сделки без красного, или включить разрывы записи.

---

## 6. Коротко

| Термин | Смысл |
|--------|--------|
| Намерение | Запись должна вестись |
| Тихий рынок | Нет сделок при живой системе — норма |
| Инцидент | Зафиксированная поломка (связь / хост / тихий обрыв) |
| Write Hole | Тишина сделок при намерении ∩ инцидент, края по last/first trade |
| Write Gap | Write Hole внутри расписания — кандидат на восстановление |

Красный на ганте writers = **Write Gap**. Причина поломки смотрите в журнале и на ленте соединения.
