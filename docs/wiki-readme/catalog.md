## 1. Две оси (не путать)

| Ось | Вопрос | Как решается в Online |
|-----|--------|------------------------|
| **Lifecycle** | Контракт ещё актуален по дате экспирации? | `instrument.active`: `true` = в Online-каталоге, `false` = архив (просрочен) |
| **Intraday** | Мы в торговой сессии / бумага торгуется прямо сейчас? | расписание, сессия, позже статус бумаги (`sec_status`) — **отдельно** от архива |

Просроченный опцион/фьючерс уходит в **архив** — его не ставят на Online-запись.
Тот же актуальный контракт ночью или на клиринге может **не торговаться**, но из каталога
не выкидывается.

Строки из базы **не удаляем**: архив нужен истории и будущей докачке. В Online-списке
по умолчанию видны только актуальные (`active`).

## 2. Опционы FORTS (ATM)

При подключении к брокеру полный набор опционов **часто не приходит** в первом справочнике.
Их подгружают отдельно по протоколу шлюза:

1. Подписка на базовый фьючерс  
2. Семейства опционов → страйки выбранной серии  
3. Окно вокруг цены фьючерса (ATM ± глубина)  
4. Загрузка кодов опционов → появление в каталоге → можно писать  

В интерфейсе:

- фьючерс можно раскрыть **даже если опционов в каталоге ещё нет**;
- при раскрытии серии система подгружает окно ATM (если справочник опционов за день ещё
  не обновляли);
- повторное раскрытие в тот же день обычно идёт из уже загруженного каталога.

Глубина окна ATM задаётся настройкой сервера (не кнопкой в UI).

## 3. Кнопка «Обновить справочник»

В карточке провайдера: рядом с настройками, **отдельная** кнопка Refresh
(`[переключатель связи][Refresh][Settings]`).

После подтверждения:

1. **Кэш справочника** — разрешить заново принять dump с коннектора; сбросить окна опционов
   (следующее раскрытие серии снова подгрузит ATM). Если сессия уже connected — нужен
   **reconnect** (текущая сессия dump не повторит); иначе dump придёт на следующем connect.
2. **Актуальность** — архивировать просроченные по дате экспирации.

В центре уведомлений это **два независимых** Group-процесса (NC): corr «кэш» —
`groupKind: action`; corr «актуальность» — `groupKind: lifecycle`. В UI ярлыки
**Action** / **Lifecycle** (не слово «Group»). Канон нитей —
[dev/phase11/to-threads.md](../dev/phase11/to-threads.md) §2.

Автоматическая проверка актуальности также выполняется раз в календарный день (МСК) при
старте сервера / первом успешном connect за день (без NC Group, пока не заведён checkup).
