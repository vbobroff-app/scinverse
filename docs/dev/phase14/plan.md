# Phase 14. CI/CD (публикация на стенд / prod)

GitHub Actions и compose-обвязка для **публикации сервисов** в org-стенд или prod.
Не для локального MVP монолита Stage 1.

**Статус:** `TODO`. **Stage:** 4. **Зависимости:** разделение сервисов (phase 11) и/или первая
публикация отдельного контура (NC / Admin Front / OHS). Бывший слот **phase 8** в старом плане
занимал CI/CD — перенесён сюда (2026-08-04).

## Критерий старта

Пайплайн нужен, когда сервис **деплоится наружу** (стенд/prod), а не только собирается локально
(`dotnet test` / `pnpm test` у разработчика). Первый кандидат — NC или Admin Front после split.

## Область (черновик)

- **14.1** CI: build + unit + integration на PR (matrix .NET / Node по затронутым пакетам).
- **14.2** Compose-сервис `migrator` (DbUp) как шаг деплоя OHS/БД.
- **14.3** CD: публикация образа/артефакта сервиса на стенд; секреты через GitHub Environments.
- **14.4** Smoke после деплоя (health / минимальный E2E).

## Вне области

- Локальный dev-loop (уже есть compose + ручные проверки) — не заменять CD.
- Полноценный multi-env GitOps — later, если понадобится.
