# catalog-basket-instruments / spec-instruments

**Часть фичи:** карточка инструмента — **реальная** спецификация и смежные вкладки
(эталон UI — Trading Finam). Индекс — [`../main.md`](../main.md).

Статус: **DRAFT** (2026-08-07). Кода отдельной поверхности ещё нет; в модалке наборов
третья колонка — урезанный read-only превью из того, что уже в Available/БД.

Смежное: [`../catalog/`](../catalog/spec.md) (модалка · T7) · board §3.2.1 ·
lifecycle (экспирация / archive).

## 1. Зачем

Сейчас экспирация и часть атрибутов дериватива часто **угадываются** из `short_name`
(`MoexFortsSpecParser`: 3-я пятница месяца). Dump `<securities>` от TRANSAQ даёт
короткий набор полей **без** полной спеки (`mat_date` и т.п.).

Последствия:

- у обычного FUT дата может отличаться от биржевой (конвенция ≠ `sec_info`);
- у спредов (`Si-9.26-12.26`) парсер намеренно не матчит → в UI экспирации нет,
  хотя у брокера карточка полная;
- третья колонка модалки не масштабируется в «настоящую» карточку инструмента.

**Канон to-be:** запрашивать спецификацию у data-сервера (TRANSAQ `get_securities_info` /
`<sec_info>` и аналоги), кэшировать, показывать в мультитаб-карточке. Догадки short_name —
только fallback, пока нет `sec_info`.

```text
инструмент (Observed / Available / Match)
  → открыть карточку spec-instruments
      → вкладки: Инфо | Торговля | Торги | Эмитент | (Новости)
      → данные: sec_info + котировки + … (не «3-я пятница»)
```

## 2. Эталон UI (Trading Finam)

Горизонтальные вкладки карточки инструмента:

| Вкладка | Смысл (эталон) | Источник данных (черновик) |
|---------|----------------|----------------------------|
| **Инфо** | Спецификация контракта: категория, группа, поставка, экспирация, последний день обращения, лот, CFI, ГО, лимиты цен, квал. инвестор… | TRANSAQ `<sec_info>` (+ то, что уже в `instrument` / `derivative`) |
| **Торговля** | Допуск операций, лонг/шорт, ставки риска, обеспечение, комиссии | брокер / sec_info / risk API (уточнить по TRANSAQ) |
| **Торги** | Bid/Ask, last, OHLC дня, объём, ОИ, диапазоны дня / 52w | marketdata / quotes (live или snapshot) |
| **Эмитент** | Инструменты по эмитенту / БА: фьючерсы · спреды | каталог Available / ISS / группировка по underlying |
| **Новости** | Лента по инструменту / БА | later (вне TRANSAQ dump; отдельный источник) |

Порядок вкладок как у эталона: Торговля → Торги → Инфо → Эмитент → Новости  
(или Инфо первой в OHS — TBD UX; канон: **мультитаб обязателен**, порядок уточним в apply).

Модалка наборов (колонка «спека») — **тонкий вход**: клик → та же модель карточки
(drawer / route), не второй независимый набор полей.

## 3. Данные: реальная спека, не догадки

### 3.1 As-is

| Слой | Что есть |
|------|----------|
| Dump `<securities>` | ticker, board, shortname, sectype, minstep, lot… — **без** mat_date |
| Enrich | `MoexFortsSpecParser` по short_name → `derivative.expiration` (FUT/OPT) |
| Спреды | short_name `Base-M1.YY-M2.YY` — **не** парсятся → expiration null |
| UI модалки | read-only поля из Available DTO |

### 3.2 To-be

| Шаг | Смысл |
|-----|--------|
| Запрос | `get_securities_info` (market + seccode / secid) при открытии карточки или лениво |
| Ответ | `<sec_info>`: `mat_date`, put/call, лот, ГО, лимиты, CFI, … (точный набор — по XML TRANSAQ) |
| Persist | кэш спеки (таблица или jsonb на instrument) + TTL / invalidate с Refresh |
| Показ | вкладка **Инфо** из кэша; fallback short_name только если sec_info ещё нет |
| Спреды | брать `mat_date` из sec_info; если биржа отдаёт одну дату — её; иначе документировать правило (ближняя нога / last trade day) **по факту ответа**, не по догадке regex |

Парсер short_name остаётся для offline / до первого sec_info и для series-дерева OPT,
но **не** SoT экспирации в карточке, когда sec_info уже есть.

### 3.3 Lifecycle

Archive / checkup по-прежнему опираются на `derivative.expiration`.  
После появления sec_info: обновлять expiration из `mat_date` при успешном ответе
(чтобы спреды и точные даты попадали в Online/архив корректно). Детали — в apply.

## 4. Поверхность / UX (черновик)

Варианты размещения (выбрать в реализации):

1. **Route** `…/instruments/:id` (или query) с табами — удобно для Observed-списка.
2. **Drawer / side panel** из модалки наборов и из основного списка.
3. Третья колонка модалки = компактный **Инфо**; «ещё» → полная мультитаб-карточка.

Инварианты:

- без Start/Auto/торговых действий в карточке v1 (запись — в основном списке);
- read-only спека + quotes;
- один источник модели для модалки и полной карточки.

## 6. Acceptance (черновик)

1. Для `Si-9.26` экспирация в карточке = `mat_date` из TRANSAQ, не обязательно 3-я пятница.
2. Для спреда `Si-9.26-12.26` после sec_info в Инфо есть дата(ы) / last day — не пусто «потому что regex».
3. Открытие карточки не требует угадывания short_name, если sec_info успешен.
4. Модалка наборов показывает те же данные Инфо (или явную ссылку «полная карточка»).
5. Мультитаб-каркас есть; пустые вкладки — честный empty/«скоро», не фейковые цифры.
